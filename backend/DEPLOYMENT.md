# Production preparation

Tarot Tree runs as one Django application with PostgreSQL and durable storage. The WSGI entry point is `config.wsgi:application`. Use a production WSGI server behind a trusted reverse proxy. PostgreSQL should be private and use a restricted application role. Apply migrations before opening traffic. Back up the database and private deck storage together and test recovery. Serve collected Admin static files over HTTPS and keep private package storage outside public roots.

## Environment

- Set `DJANGO_ENV=production`, `DJANGO_SECRET_KEY` with at least 50 unpredictable characters, explicit `DJANGO_ALLOWED_HOSTS` and `DATABASE_URL`. Production uses secure cookies, HTTPS redirects and HSTS. Enable `TRUST_PROXY_HTTPS=true` only with a trusted proxy which overwrites the forwarded HTTPS header. Restrict traffic to the proxy and use explicit approved hosts in `CORS_ALLOWED_ORIGINS` for any browser clients.
- Set `TAROT_STORAGE_ROOT` for private deck packages and collect static files with `python manage.py collectstatic`. To move packages to another storage backend, replace the `deck_packages` storage implementation. Keep reads authenticated and preserve checksum and immutable names when migrating files.
- Provision SMTP and a verified sender before turning on `EMAIL_VERIFICATION_ENABLED`. Outbound transport is SMTP over STARTTLS. Keep email verification off until the delivery path is working. Authenticated Oracle/guest development and the public catalog can run with it off.
- Use Django Admin staff groups with only the required model permissions. Restrict access to administration at the reverse proxy. Provider route configuration, credential references, health checks, usage, personalities, deck metadata, versions and asset manifests, orders, payment events, grants, users, identities and token revocations are available to authorized staff. Oracle dialogue and image uploads are absent from Admin.
- Run `python manage.py check --deploy` with the production environment. Keep request bodies, bearer tokens, checkout URLs, raw AI responses and email claims out of infrastructure and application logs.

## AI providers

The `AI_ORACLE_ALLOWED_HOSTS` and `AI_VISION_ALLOWED_HOSTS` variables restrict hostnames per service, and `AI_ALLOWED_HOSTS` is a shared allowlist. Prefer separate lists. Enter bare hosts or IP literals and use HTTPS in production. The egress firewall should allow only the required operator-controlled endpoints and use trusted DNS. HTTP redirects, URL query strings and embedded credentials are rejected. Credential references use names such as `AI_CREDENTIAL_ORACLE_2026`. Set the value in process secrets, then select the reference in Admin. Rotate with a new reference and secret followed by removal of the old credential. App-level changes to provider, model and routing require no Flutter rebuild. The set of supported protocols is established in Python.

- **Gemini or a cloud LLM** can use the Oracle OpenAI-compatible adapter if the endpoint accepts bearer authorization and the documented `messages`, `model`, `stream` and `max_tokens` shape. The response is read from `choices[0].message.content`. Configure the provider in Admin and check that its structured synthesis respects the public Oracle contract.
- **Ollama or an equivalent local LLM** can use an OpenAI-compatible chat endpoint from the backend's network. A native protocol can be added as a separate `OracleProvider` adapter. Local inference remains a separate operator service.
- **DINOv2 or another recognizer** can sit behind the Vision HTTP v1 adapter or a future provider-specific adapter. The Vision adapter posts `model`, `system`, optional `deckId` and `items` with `itemId`, `mimeType` and `imageBase64`. The provider returns `{"results":[{"itemId":"crop-1","status":"recognized","candidates":[{"cardId":"tarot:13","orientation":"upright","score":{"type":"similarity","value":0.91}}]}]}`. It must return one result per request item. Document the score scale and source in the inference integration.
- **Home RTX 3080** can host either adapter behind an operator-managed authenticated endpoint. If it goes offline, each router follows its own policy. Enable a paid fallback only by saving an explicit policy for the corresponding capability. Disabling a higher-ranked route preserves the fallback restrictions. A configured paid primary or explicit personality override must have a daily budget and conservative USD ceiling per attempt, including the maximum token allowance and batch size.
- Use a short operator-controlled `health_path` for connectivity checks. Admin displays the recorded check time and status. Health endpoints report provider reachability. Exercise inference separately with controlled requests.

## Payments

A future processor is implemented through `PaymentProvider`. It should use the order UUID as its external idempotency key, verify the provider's raw webhook signature, and independently verify merchant identity, order reference, amount, currency and status before returning a trusted event. The development implementation authenticates test events by HMAC and is locked out in production. Choose payment adapters by supported distribution channel and verify current Google Play or App Store billing rules before release. Refund initiation is provider-specific, while verified refund events already revoke matching grants.

## Capacity, failure recovery and retention

Apply reverse-proxy rate and connection limits for public endpoints and strict body limits for auth, JSON and webhooks. Set caps of 21 MiB for Vision multipart requests and about 102 MiB for Admin package uploads. The Django Vision upload handler also enforces streamed file and batch limits. Requests are synchronous and workers need bounds on execution time and concurrency. Provider limits are database-backed and shared by workers using the same PostgreSQL instance. The configured spending limit is a conservative reservation in USD based on a maintained per-attempt ceiling, with provider-native billing caps appropriate for production. Keep database time synchronized. Fixed windows and IP limits are coarse controls when users share a proxy or rotate addresses. Configure network-layer rate limits using the verified client address.

An unresolved checkout remains visible as `pending` for provider-specific reconciliation. Reusing its key yields the same order. Oracle releases stale session ownership after ten minutes on the next session operation and records an unknown result. The caller can then make a deliberate new request. Vision rows left in `recognizing` after an interrupted synchronous worker are pruned with other expired recognition records. Leases expire after an adapter's configured deadline and grace period. Bound worker execution to the capacity the deployment can support.

Run `python manage.py prune_backend_data` to inspect retention and `python manage.py prune_backend_data --apply` to apply the documented windows daily. The command removes expired credentials, short-lived counters, transient recognition records and guest identities older than 30 days without a live token. Django upload handling deletes temporary image files at the end of a request. Use an isolated temporary directory with an operating-system age policy for files orphaned by a killed worker. Image assets in the store have separate durable storage. Guests and verified accounts can delete their own readings and associated replay data using the API. Verified reading history stays until deleted. Keep order and entitlement history according to the deployment's financial retention policy and apply database backup retention separately.
